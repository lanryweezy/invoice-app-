## 2026-07-07 - Testing hooks that rely on syncToCloud
**Learning:** In `apps/web/hooks/useInvoice.ts`, state mutations like `saveInvoice` often trigger side-effects like writing to `localStorage` and pushing to the cloud via the `syncToCloud` utility function. `syncToCloud` relies on Firestore implementations (like `queueMutation`).
**Action:** When unit testing data-handling hooks in `apps/web` (like `useInvoice`), always ensure browser globals like `localStorage` are explicitly stubbed via `vi.stubGlobal('localStorage', { setItem: vi.fn(), getItem: vi.fn() })`. Do not attempt to mock `syncToCloud` directly since it is internal to the hook; instead, observe the effects (like changes in the hook's returned state and calls to `localStorage`). Use `vi.useFakeTimers()` to ensure any debounced effects triggered by updates complete synchronously during testing.
