## 2024-07-06 - Test Coverage in InvoiceApp Monorepo
**Learning:** This repo has a monorepo structure with tests in `apps/web`. Vitest and `@vitest/coverage-v8` handle testing and coverage reports. Vitest is configured to run tests over all files via `pnpm -w run test`. Coverage for specific files requires installing the dependencies properly. The `offlineSync.ts` file initially had zero testing for its core offline sync behaviour.
**Action:** When adding tests in `apps/web/utils`, always write complete test suites using `vitest` covering all logical branches. We added 100% test coverage to `offlineSync.ts`.
## 2024-07-06 - useInvoice.ts Client Save Testing
**Learning:** The `saveClient` function inside `hooks/useInvoice.ts` is responsible for case-insensitive client deduplication, alphabetical sorting, updating `localStorage`, and triggering `syncToCloud`. Since `syncToCloud` interacts with both Firebase (`setDoc`) and the offline queue (`queueMutation`), any test covering `saveClient` needs to correctly mock `../services/firebase` and `../utils/offlineSync` to prevent real side effects or network timeouts.
**Action:** Always mock `services/firebase` and `utils/offlineSync` when writing tests for hooks that interact with offline-first or cloud-sync behaviours in this repo. Use isolated hook renders (`renderHook`) and `vi.clearAllMocks()` / `localStorage.clear()` in `beforeEach` to ensure no cross-test state leakage.
